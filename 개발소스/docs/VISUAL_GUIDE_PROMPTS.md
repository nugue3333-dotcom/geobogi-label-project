# 채움LAB 시각 안내 프롬프트

긴 사용안내에서 고객이 직접 해야 할 일을 먼저 추려 네 가지 형식으로 보여준다. 이 문서의 `/Infographic`, `/ComicStrip`, `/StickyNotes`, `/Timeline`은 출력 형식을 지정하는 프롬프트 표기다. 앱에 설치된 명령이나 자동 실행 기능이 아니다.

## 이번에 적용한 결과

| 형식 | 채움LAB 적용 대상 | 고객 전달물 |
|---|---|---|
| `/Infographic` | 프린터 설정·상품 DB·도안·출력 파일의 관계 | PDF 1쪽: 처음 설정 |
| `/ComicStrip` | 스캔 → 행 선택 → 확인 → 첫 장 출력 | PDF 2쪽: 매일 사용 4컷 |
| `/StickyNotes` | 연결·라벨·바코드·인식 값·대상·매수 확인 | PDF 3쪽: 인쇄 전 확인 |
| `/Timeline` | 설치 전부터 첫 장 검증·반복 출력까지의 순서 | PDF 4쪽: 설치·출력 순서 |

- 고객용 PDF: 소스 루트 `한눈에_사용안내.pdf`.
- PDF 생성 원본: `scripts/build_quick_customer_guide.py`. 별도 웹 안내 원본은 `docs/visual-guides/한눈에_사용안내.html`.
- 원본 HTML은 인터넷 없이 열린다. 탭과 수동 체크리스트를 지원하며 고객 데이터는 저장하지 않는다.
- 고객 폴더에는 PDF를 전달한다. HTML은 기존 배포 금지 규칙에 따라 개발 문서에만 둔다.
- `도움말 > 빠른 사용안내`는 `사용안내.txt`를 연다. 한눈에 PDF는 패키지 폴더에서 직접 연다. `도움말 > 고객용 매뉴얼`은 현재 프로그램의 상세 PDF를 연다.

## 입력 근거

내용을 수정하기 전에 다음 파일의 현재 내용을 읽는다.

1. `README_먼저읽기.txt`, `사용안내.txt`, `설치_및_사용_메뉴얼.txt`.
2. `barcode_label_automation/label_manager_app.py`와 해당 동작의 테스트.
3. 프로젝트 루트의 `docs/PRODUCT_PACKAGES.md`, `docs/MARKETING_AUTOMATION_RULES.md`, `docs/DESIGN_SYSTEM.md`.
4. 고객 배포 변경 시 `scripts/build_release_exes.ps1`, `barcode_label_automation/release_manifest.py`, `docs/RELEASE_CHECKLIST.md`.

현재 제작 확인 기준은 `2026.10.06.01` 실제 실행 코드와 고객 매뉴얼이다. 과거 요약이나 이미지 속 설명을 현재 기능의 근거로 쓰지 않는다.

현재 인쇄 구현은 체크한 행이 있으면 해당 항목, 없으면 전체 유효 항목을 대상으로 한다. 항상 인쇄 매수 선택에서 대상 수와 매수를 확인하며, 취소하면 명령을 보내지 않는다. 매수는 임시 큐에만 반영한다.

## 공통 작성 규칙

- 독자는 현장에서 프로그램을 사용하는 고객이다. 메뉴명과 파일명은 현재 프로그램 표기를 그대로 사용한다.
- 한 화면에는 한 작업을 설명하고, 순서·조건·실물 확인을 생략하지 않는다.
- 바코드는 문자열로 다루며 앞자리 0을 보존한다. 설명용 예시를 실제 설정 바코드나 실제 상품 데이터로 제시하지 않는다.
- mm와 DPI는 실제 장비·라벨을 확인해 입력하도록 안내한다. 임의의 기본값이나 장비 호환성을 만들지 않는다.
- OCR로 얻은 글자·바코드는 원본과 대조하고 확정한다. 미확인 값은 출력하지 않는다.
- 파일 생성·미리보기와 실제 프린터 전송을 구분한다. 전송 완료를 실물 출력 성공으로 표시하지 않는다.
- 체크한 항목, 인쇄 매수 선택, 취소 동작을 정확히 설명한다.
- 가격·할인·지원기간·보증·환불·배송·외부 연동 조건은 확인된 정책을 유지한다.
- 입력에는 가상의 상품 예시만 사용한다. 고객 원문, 연락처, 주소, 인증정보, 사설 장비 설정값을 넣지 않는다.
- 확인할 수 없는 값은 `확인 필요`로 표시하고 근거 없는 기능·수치·기한으로 빈칸을 채우지 않는다.

## 바로 재사용하는 프롬프트

각 프롬프트 아래의 `<현재 자료>`를 확인한 문서 내용으로 채운다. 형식만 바꾸고 조건이나 실제 동작은 바꾸지 않는다.

### 처음 설정 한 장

```text
/Infographic
채움LAB 고객이 처음 라벨을 출력하기 위해 해야 할 일을 한 장의 한국어 인포그래픽으로 작성해.
프린터설정.exe → 상품 DB 연결 → 라벨디자이너.exe → 출력 파일 생성 → 첫 장 실물 확인 순서를 사용해.
각 단계에는 실행할 프로그램, 확인할 값, 다음 단계로 넘어갈 조건을 각각 한 줄로 적어.
프린터 연결 방식, 라벨 폭·높이(mm), DPI는 실제 장비값을 확인하도록 적고 숫자를 추정하지 마.
DB의 바코드 열은 문자로 관리해 앞자리 0을 보존하고, 인식 값은 원본과 대조 후 확정하도록 적어.
파일 생성은 프린터 전송이 아니며, 첫 장 출력 후 라벨 위치와 스캐너 판독을 확인하도록 적어.
공통 작성 규칙과 아래 자료만 사용해. 자료에 없는 기능·가격·모델·호환성을 추가하지 마.
<현재 자료>
```

### 매일 사용 4컷

```text
/ComicStrip
채움LAB의 반복 라벨 출력 업무를 한국어 4컷 안내로 작성해.
1컷: 라벨출력관리.exe에서 상품 DB를 연결하고 DB 상품조회 입력칸에 커서를 둔다.
2컷: 바코드를 스캔하고, 중복 결과가 있으면 원하는 행을 선택해 확인한다.
3컷: 출력 대상 행을 체크하고 인쇄파일 생성으로 바코드·내용·도안 경계를 확인한다.
4컷: 인쇄 매수 선택에서 대상과 매수를 확인하고, 한 항목 1매로 먼저 출력해 실물을 검증한다.
체크한 행이 있으면 해당 항목, 없으면 전체 유효 항목이 대상이며 매수 확인이 필요하다고 명시해.
매수 선택 취소는 프린터 전송을 하지 않는다고 적어.
각 컷은 짧은 행동 문장과 단순한 설명용 그림으로 구성해. 장비 사진이나 설정 바코드를 지어내지 마.
전송 완료는 실제 라벨 배출 완료가 아니라는 확인 문구를 마지막에 넣어.
<현재 자료>
```

### 인쇄 전 확인 메모

```text
/StickyNotes
채움LAB에서 인쇄 전에 사람이 확인할 여섯 항목을 포스트잇 형식의 한국어 체크리스트로 작성해.
연결·라벨 규격, 바코드 문자값·앞자리 0, 원본과 인식 값 대조, 출력 대상 행, 매수 선택, 생성 파일 확인을 사용해.
각 메모에는 확인 행동과 잘못됐을 때 먼저 돌아갈 화면을 적어.
체크는 사람이 확인했다는 기록이며 실제 장비 진단이나 출력 성공 인증이 아니라고 명시해.
체크 완료만으로 실제 인쇄가 시작되거나 장비 설정이 바뀌는 기능은 넣지 마.
확인되지 않은 항목은 그대로 미확인 상태로 두고 임의로 완료 처리하지 마.
<현재 자료>
```

### 설치·출력 순서

```text
/Timeline
채움LAB 고객의 설치·첫 출력·반복 출력 순서를 한국어 타임라인으로 작성해.
설치 전 백업/폴더 확인 → 배포본 설치 점검 → 프린터·라벨·DB·도안 확인 → 출력 파일 생성 → 한 항목 1매 실물 검증 → 반복 출력의 순서로 구성해.
각 단계에는 시작 조건, 할 일, 통과 기준을 적어.
기간과 완료 날짜는 실제 일정 자료가 있을 때만 넣고, 자료가 없으면 순서만 표시해.
실제 첫 장이 배출되고 스캐너 판독이 확인된 뒤 반복 출력으로 넘어가게 해.
전송이 중단돼 출력 여부가 불명확하면 실물을 먼저 확인하고 명시적으로 재전송 여부를 결정하도록 적어.
<현재 자료>
```

## 원본과 고객 PDF 갱신

HTML의 네 탭을 수정한 뒤 데스크톱, 모바일 폭, 키보드 조작, 브라우저 인쇄를 확인한다. PDF는 모든 섹션을 표시하고 각 섹션을 새 페이지로 시작해 A4 4쪽으로 출력한다. 렌더링된 PDF의 네 쪽을 직접 확인하고 한글·바코드 문자열·메뉴명이 잘리거나 바뀌지 않았는지 대조한다.

PDF와 안내문은 현행 릴리스 게이트에서 고객용 실행폴더 및 상위 최종 폴더로 해시 대조 복사한 뒤 manifest에 포함한다. 기존 고객 폴더에 PDF만 추가하거나 안내문만 덮어쓰고 기존 manifest를 유지하지 않는다. 이번 작업은 릴리스 게이트의 안내문 동기화를 준비하며 실제 EXE 빌드·프린터 전송·고객 배포를 실행하지 않는다.

효과는 이후 설치 문의 건수, 설치 실패율, 지원 문의율로 측정할 수 있다. 이번 작업에서 문의 감소나 설치 성공률 향상을 측정한 것으로 표시하지 않는다.
