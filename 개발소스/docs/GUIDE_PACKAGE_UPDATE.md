# 고객 안내 갱신본 준비

실행 파일을 바꾸지 않는 안내 수정은 검증된 고객 패키지의 복사본에 적용한다. 원본 고객 폴더는 보관하고, 새 폴더에서 안내와 배포 파일 목록을 확인한다. 이 도구는 고객에게 보내거나 프린터로 출력하지 않는다.

## Windows에서 실행

최신 소스를 받은 뒤 `개발소스` 폴더에서 실행한다. 개발용 `.venv\Scripts\python.exe`와 원본 고객 폴더의 정상 `release_manifest.json`이 필요하다. 프로그램을 닫고 파일 복사가 끝날 때까지 원본 폴더를 수정하지 않는다.

먼저 쓰기 없는 점검을 실행한다. 출력 폴더는 아직 존재하지 않는 새 경로를 지정한다.

```cmd
안내_갱신본_만들기.cmd "..\고객배포\채움랩_안내갱신본_01"
```

점검이 통과하면 같은 명령에 `--apply`를 붙여 새 폴더를 만든다.

```cmd
안내_갱신본_만들기.cmd "..\고객배포\채움랩_안내갱신본_01" --apply
```

다른 원본 폴더를 지정하거나 CMD 없이 실행할 때는 다음 명령을 사용한다.

```powershell
.\.venv\Scripts\python.exe -m barcode_label_automation.customer_guide_package --customer-dir .\고객용_실행폴더 --guides-dir . --output-dir ..\고객배포\채움랩_안내갱신본_02 --apply
```

## 갱신 범위와 확인 결과

- `한눈에_사용안내.pdf`, `README_먼저읽기.txt`, `사용안내.txt`를 최신 안내로 바꾼다.
- `배포_파일목록.txt`와 `release_manifest.json`을 새 복사본 기준으로 갱신한다. HTML 원본은 고객 폴더에 넣지 않는다.
- 원본 EXE, `버전정보.txt`, 설정, 상품 DB, 인쇄 데이터, 템플릿의 바이트를 보존한다. 원본에 실제 고객 데이터가 있다면 새 복사본에도 유지되므로 전달 전 기존 개인정보 점검 절차를 따른다.
- 원본 빌드 ID, Python/PyInstaller 버전, spec 해시, 기존 테스트 기록, 패키지명·버전·생성시간을 보존한다. 안내 갱신 시간·SHA-256만 `docs_updates`에 별도로 기록하며 EXE를 새로 빌드한 것으로 표시하지 않는다.
- 로그, 출력 파일, 백업 폴더 등 고객 배포 제외 항목은 복사하지 않는다.
- 원본이나 입력 안내가 손상됐거나 링크 경로인 경우, 출력 폴더가 이미 존재하는 경우에는 완료 폴더를 만들지 않는다. 원본 payload 변경이 최종 검증에서 감지돼도 생성하지 않는다. 안내 입력은 처음 읽은 바이트를 사용하므로 복사가 끝날 때까지 수정하지 않는다. 원본을 보관하므로 복구는 기존 원본 폴더를 계속 사용하면 된다.

manifest 통과는 파일 구성·바이트 검증 결과다. Windows 실행, 장비 연결, 실제 라벨 배출·스캔, 고객 배포 승인 결과가 아니다. 고객 전달 전에는 기존 `docs/RELEASE_CHECKLIST.md`의 해당 확인 항목과 고객 폴더의 `00_고객PC_실행전점검.cmd`를 수행한다. 실행 파일이나 인쇄 기능을 바꾼 경우에는 문서 갱신 도구 대신 기존 6개 EXE 릴리스 게이트를 사용한다.
