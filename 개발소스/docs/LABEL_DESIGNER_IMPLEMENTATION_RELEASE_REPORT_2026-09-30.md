- 여섯 EXE, 고객 안내문, DOCX, PDF, 시작 명령, 예제 라벨을 소스·고객 실행폴더·상위 최종 폴더·새 배포본에서 SHA-256으로 대조했다.
- 고객 실행폴더와 새 배포본의 배포 대상 **152개 파일, 308,217,159바이트**는 모두 같은 해시다. 패키지별 이름과 생성 정보가 들어가는 `release_manifest.json`, `버전정보.txt`, `배포_파일목록.txt`는 별도 메타데이터다. 두 manifest 모두 검증을 통과했다.

`config.ini`, `print_queue.xlsx`, `barcode_db.xlsx`, `labels.xlsm`은 고객이 수정하는 설정·데이터다. 기존 고객 실행폴더 값을 보존해 새 배포에 복사했다. 소스나 상위 최종 폴더의 사용자 데이터와 바이트 단위로 같게 만들기 위해 덮어쓰지 않았다. 네 위치의 `templates/default_label.json`은 모두 개체 0개다.

## 4. 고객 현장 확인과 남은 제한

1. 실제 프린터와 용지, 203/300dpi별로 **1D와 2D를 각각 인쇄·스캔**하고 여백·가독성·중복 출력 여부를 확인해야 한다. 드라이런과 전송 성공은 실물 배출을 증명하지 않는다.
2. 다른 PC에서 `.gbproject` 이미지·글꼴·엑셀 재연결, 백업·복원, 권한과 파일 연결을 확인해야 한다.
3. 화면읽기 도구의 컨트롤 이름과 키보드 전체 흐름은 아직 실사용 검증을 하지 않았다. 대용량 출력 준비는 여전히 UI 스레드에서 수행한다. 전용 단일 실행 아이콘도 아직 제공하지 않는다.
4. DOCX는 구조·문구·해시를 검증했지만 이 PC에서 LibreOffice가 없고 Word COM 열기가 실패해 페이지별 시각 확인을 하지 못했다. PDF 전 페이지는 시각 확인했다.
5. GitHub `main`에 2026-10-01 최신 소스·테스트·고객 매뉴얼·EXE 6종을 반영했다. 릴리스 커밋은 `64848106eed0948447fa9557716b6992f84cbdfb`이다. 로컬 Git의 DNS 오류로 GitHub 연결을 사용했고 기존 원격 이력을 보존했다. 로컬 HEAD와 작업 트리는 자동으로 변경하지 않았으므로, 로컬 Git 동기화는 네트워크 복구 후 별도로 확인해야 한다.
6. 고객 환경 점검은 통과했지만 공용 런타임 폴더의 오래된 `_MEI` 임시 폴더 7개에 접근 권한 경고가 있었다. 이번 배포 payload에는 포함되지 않았다.

현장 판매 범위는 엑셀 상품의 반복 라벨 출력과 장비 설정·지원이 필요한 고객에 맞춘다. BarTender의 `.btw` 직접 호환이나 기업용 승인·권한·이력 기능을 주장하지 않는다.

## 5. 2026-10-01 재확인

고객 실행폴더와 `20260930_02` 배포본의 release manifest를 다시 검증해 둘 다 통과했다. 배포 대상 152개 파일(308,217,159바이트)과 소스 루트·배포본의 EXE 6종도 SHA-256이 다시 일치했다.

GitHub 연결을 통해 릴리스 커밋 `64848106eed0948447fa9557716b6992f84cbdfb`를 생성하고 `main`을 강제 덮어쓰기 없이 갱신했다. 소스·매뉴얼·EXE와 실행 안내 등 150개 경로를 갱신했고 구형 EXE 2개와 오래된 안내문 3개를 제거했다. 루트에 `최신버전_안내.md`를 추가했다. 업로드한 56개 파일의 Git blob SHA를 로컬 바이트로 계산한 SHA와 대조했다. 고객 엑셀 원본·개인 설정·DB·출력 로그는 새로 업로드하지 않았다.
