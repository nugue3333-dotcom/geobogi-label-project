# 바코드 편집창: 우선순위 재검토 보고서

2026-10-13 · 검토 대상 2026.10.13.04 · 수정 전 검토안

## 1. 판단

현재 GS1 편집창은 기본 입력 작업을 완료하기 어려운 상태입니다. 창 크기와 공간 배분을 먼저 검수했어야 했습니다. 이전의 6,863건 통과·GUI 87개 통과는 GS1 입력창의 사용성 완료를 입증하지 않습니다. 이 부분을 완료로 보고한 판단을 바로잡습니다.

**우선순위는 창에 맞게 표시 → 실제 입력·수정·저장·닫기 → 오류 복구 → 매뉴얼·배포입니다.**

## 2. 현재 화면에서 확인한 사실

프로그램을 임시 데이터 폴더에서 실행해 일반 바코드의 GS1 버튼으로 진입했습니다. 새 전체 테스트나 빌드는 실행하지 않았습니다.

| 실제 창 | GS1 페이지 높이 | 아래 미리보기 높이 | 확인한 문제 |
| --- | ---: | ---: | --- |
| 1262×809 | 398px | 247px | 고정값·추가·선택 수정·데이터 검증이 GS1 페이지 밖에 있음 |
| 1024×740 | 329px | 247px | 같은 입력·버튼 잘림, 검색칸 위 마우스 휠 스크롤 실패 |

현재 환경의 작업 영역은 2560×1392입니다. 위 숫자는 창 크기별 재현 결과이며 Windows 배율별 검증 결과가 아닙니다. 첨부 이미지만으로 사용자 모니터 해상도나 창 전체의 화면 이탈 여부를 확정하지 않습니다.

### 코드상 원인

1. **미리보기에 공간을 먼저 배정합니다.** 기본 창 폭은 1280인데 GS1/UDI 페이지의 전환 기준은 1320입니다. 기본 창에서 미리보기가 아래로 이동하고, 미리보기 행이 높이를 확보한 뒤 입력 행이 남은 높이를 받습니다.
2. **입력창이 부모 높이에 맞춰 줄어들지 않습니다.** 내부 편집기를 담는 프레임에 행 확장 설정이 빠졌습니다. 1262×809 재현에서 GS1 편집기 높이는 488px인데 배정된 페이지는 398px였습니다.
3. **중복 영역이 높이를 추가로 씁니다.** GS1 자체 원문·상태 표시와 바깥 미리보기의 원문·상태가 동시에 표시됩니다. 빈 미리보기에서도 247px를 차지했습니다.
4. **스크롤 입력이 연결되지 않습니다.** GS1 내부 프레임의 휠 연결과 상위 편집창의 이벤트 처리가 맞지 않습니다. 검색칸에서 휠을 내려도 내부 스크롤 위치가 변하지 않는 것을 재현했습니다.

빈 GS1에서 “AI를 하나 이상 추가” 안내가 나오는 것은 초기 상태입니다. 이 화면의 핵심 결함은 값을 넣는 입력칸과 버튼에 도달하기 어렵다는 점입니다.

| P0-2 | GS1 입력 구조와 스크롤 | AI 선택 → 고정값/DB 입력 → 추가·수정 → 검증 → 적용·닫기를 실제 화면에서 완료 |

## 4. 권장 구조: 입력 우선, 미리보기는 버튼으로 열기

- 상단: 채움랩 로고, 바코드 종류, **미리보기** 버튼. 제목과 빈 여백을 줄입니다.
- 왼쪽: 데이터 원본 / 바코드 종류·크기 / 표시문자. GS1·UDI는 선택할 때만 추가합니다.
- 본문: 입력 영역에 높이를 배정합니다. GS1의 AI 목록과 구성 목록은 남는 높이에 맞춰 줄어듭니다. 선택 AI·고정값/DB·추가/수정 버튼을 먼저 확보합니다.
- 작은 화면: AI 목록을 접거나 선택 패널로 전환하고 입력부는 한 열로 배치합니다. 필요한 본문 스크롤은 휠과 Tab으로 도달할 수 있어야 합니다.
- 결과 확인: 인코딩 값·표시문자 요약을 한 곳에 표시합니다. 코드 그림·확대·DB 행 비교는 **미리보기** 버튼으로 엽니다. 아래에 큰 미리보기를 항상 펼치는 기존 제안을 수정합니다.
- 하단: 데이터 검증 / 취소 / 적용 / 확인을 고정합니다. 검증 오류 중에도 취소·닫기에 도달할 수 있어야 합니다.

별도 미리보기 창에서도 닫기·Esc가 작동하고, 돌아오면 입력 중이던 위치와 값을 유지합니다. 일반·GS1·UDI·크기·표시문자 페이지에 같은 공간 배분 규칙을 적용합니다.

## 5. 검증 기준을 바꾸는 이유와 새 합격 기준

기존 창 크기 검사는 일반 데이터 첫 페이지만 확인했습니다. GS1/UDI는 예제 주입과 내부 함수 호출로 입력을 건너뛰었습니다. `winfo_ismapped()`와 `.invoke()`는 화면 밖에 잘린 버튼도 성공으로 처리할 수 있습니다.

다음 수정의 UI 합격 기준은 아래 여섯 가지입니다.

1. 실제 작업 영역·창 크기·Windows 100/125/150/200% 배율에서 일반·GS1·UDI·크기·표시문자 페이지를 확인합니다. 배율로 공간이 부족하면 접기·한 열 배치·스크롤을 실제로 확인합니다.
2. 보이는 AI 검색·선택·값 입력·추가·수정·검증·적용 버튼과 키보드만으로 작업을 끝냅니다. 내부 예제 주입으로 대체하지 않습니다.
3. DB 열 연결과 두 행 전환 후 화면 값·미리보기 판독값·저장 후 재열기 값이 일치합니다.
4. 길이·체크숫자·날짜·DB 누락 오류를 직접 입력하고 수정합니다. 값이 유지되고 문제 위치와 수정 방법이 표시됩니다.
5. 각 페이지·스크롤 위치·오류 상태에서 취소·X·Esc 및 미리보기 닫기를 확인합니다. 마지막 적용값을 보존합니다.
6. 실제 고객 EXE에서 같은 경로를 재검수합니다. 버튼의 실제 표시 영역·클릭 가능 여부와 단계별 캡처를 확인한 뒤 자동 회귀 검사와 배포 검증을 진행합니다.

**출시 조건: P0 기본 작업 흐름에 잘림·조작 불가가 남으면 UI 완료로 판정하지 않습니다.**
