# 에이전트 회의 프로토콜

이 프로젝트의 멀티 AI 에이전트는 단순 병렬 실행이 아니라 공유 회의록을 통해 서로의 의견을 읽고 반박, 보완, 합의, 구현, 검증을 진행한다.

## 라운드

1. 문제 진단
   - 파일 수정 금지.
   - 사용자 목표, 현재 구조, 재현 가능성, 위험, 누락 정보를 정리한다.
   - 다른 에이전트가 놓치기 쉬운 문제를 명시한다.
2. 해결안 토론
   - 파일 수정 금지.
   - 앞선 진단을 읽고 동의/반대/보완점을 적는다.
   - 가장 작고 되돌리기 쉬운 구현안을 추천한다.
3. 합의안 구현
   - 배정된 쓰기 범위가 있는 에이전트만 파일을 수정한다.
   - 구현 전 합의안을 한 줄로 요약하고, 그 범위 밖 변경은 하지 않는다.
   - 다른 에이전트의 변경을 되돌리지 않는다.
4. 검증과 출시 판단
   - 테스트, 빌드, 드라이런, 고객 실행 표면 검증을 실행한다.
   - 성공, 실패, 미실행 항목을 분리한다.
   - 외부 효과가 있는 실제 출력/발송/운영 변경은 명시 요청 없이는 하지 않는다.

## 발언 규칙

- 이전 라운드의 `transcript.md`를 근거로 답한다.
- 의견 차이가 있으면 결론만 쓰지 말고 어떤 위험 때문에 반대하는지 적는다.
- 구현보다 검증이 더 중요한 문제면 구현 보류와 검증 명령을 우선 제안한다.
- 최종 발언에는 변경 파일, 실행 검증, 남은 위험을 포함한다.
